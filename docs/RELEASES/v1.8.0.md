# U4Claude v1.8.0

The sign-in flow moves to your browser, plus a new display option and a batch of correctness and localization fixes.

## What changed

- **Sign in with Claude — system-browser OAuth.** "Add account" no longer loads claude.ai inside an embedded `WKWebView`. It opens your default browser for the Claude OAuth (PKCE) flow and returns automatically via a short-lived `localhost` callback. This unblocks Google, Microsoft, enterprise SSO, and passkey logins that never worked inside the embedded WebView (closes upstream [Issue #49](https://github.com/f-is-h/Usage4Claude/issues/49)). OAuth accounts read usage with a Bearer token against Anthropic's OAuth endpoint and skip the Cloudflare header path entirely — no spoofed Chrome user-agent, no cookie scraping. Your OAuth refresh token lives in the Keychain like a session key. Existing session-key accounts are untouched and keep the embedded WebLogin as a fallback.
- **Custom display can be scoped to the menu bar only.** A new toggle under General Settings → Display: when on, your custom limit selection applies to the menu-bar icon while the popover falls back to smart display and shows every limit that has data.
- **Extra Usage no longer silently disappears.** The `used_credits` field is now decoded as a floating-point value; when the API returned a fractional amount (e.g. `21.0`) the old integer decoder threw and dropped the entire Extra Usage row. Also adds the newer `monthly_limit` field.
- **Expired session keys report the right error.** During login/manual-key validation, an expired key returned a misleading "Cloudflare blocked" message; it now correctly reports the session as expired.
- **Localization fixes.** The HTTP-error message (e.g. an unexpected status code) was hardcoded in Chinese for every user — it's now localized in all five languages. The popover's authentication-error "Go to Settings" button was only appearing for English and Simplified Chinese users; it now appears in Japanese, Korean, and Traditional Chinese too.

## Internal

- New OAuth stack: `Services/ClaudeOAuth/` (config + token endpoint) and a provider-neutral `Services/OAuth/` (`PKCE`, `OAuthCallbackServer`), plus `ClaudeOAuthCoordinator` / `ClaudeOAuthLoginView`. Usage fetch coalesces concurrent token refreshes (single-flight) and caches the access token, with silent write-back on refresh-token rotation.
- The OAuth callback listener accepts loopback peers only. It binds the wildcard address (so a browser resolving `localhost` to either `127.0.0.1` or `::1` connects), but rejects any non-loopback peer before reading a byte — closing a LAN denial-of-service where a stray request could abort a sign-in. Handles the IPv4-mapped-IPv6 case and the full `127.0.0.0/8` block.
- Adds the `com.apple.security.network.server` entitlement, required for the sandboxed loopback listener.
- Multi-account robustness: the current-account id uses a `DEBUG_`-prefixed key so Debug and Release builds don't collide on the shared `UserDefaults` domain, plus a first-account fallback for an unresolvable stored id. Backport of upstream `bd019d7`.
- +2 `ExtraUsageResponseTests` (fractional credits, `monthly_limit` precedence). 55/55 `swift test` pass; Debug and Release builds clean, no new warnings.

## Heads-up on update

None required. This release touches no Keychain access groups, so the Sparkle update installs seamlessly and existing accounts keep working — **no re-login required**. If you want the new browser sign-in (for SSO/passkey), just remove and re-add the account.

## What stays unchanged

Legacy session-key accounts continue to work exactly as before — same cookie-based fetch, same Cloudflare header path, same embedded WebLogin. The browser OAuth flow is an addition, not a replacement, for those accounts.
