# U4Claude v1.9.3

Four fixes ported from upstream. The headline one: accounts whose plan returns a null 5-hour window were getting nothing at all — no numbers, no history, and a diagnostic that blamed their credentials.

## What changed

- **A missing 5-hour limit no longer wipes out the whole reading.** The 5-hour window was the only limit the app insisted on. If Claude returned it as empty — which happens on some Team plans — the entire response was discarded, even when the 7-day and per-model numbers in it were perfectly good. The app now reads whatever the response actually contains and simply leaves the 5-hour row out when there isn't one.
- **Plans without a usage dashboard now say so.** Free accounts, and Team/Enterprise organizations that haven't switched on the member usage dashboard, get back a valid but completely empty reading. That used to surface as "Failed to parse response data. Please check if your credentials are correct." — which sent people off re-entering credentials that were never the problem. The message now explains that the plan doesn't provide usage data, and points at asking an organization admin or checking the dashboard in a browser. The built-in diagnostic says the same thing, and states plainly that the credentials are valid.
- **A failed refresh no longer throws away the numbers you were looking at.** A single flaky request used to replace the whole popover with an error page. Now the readings stay on screen with a small "Showing cached data" banner above them, and the banner opens diagnostics if you click it. Errors you actually need to act on — signing in again, a Cloudflare challenge, or a plan with no usage data — still take over the popover, because they carry instructions worth reading.
- **The settings tab strip no longer gets clipped.** The tab row could be pushed up past the top edge of the window, where part of it stopped being clickable, if a tab's content grew taller than the window. Content now overflows downward instead, and the tab buttons hold a fixed size so the strip stops shifting as you switch tabs.

## Internal

- `UsageResponse.five_hour` is Optional. It was the only non-optional window, so a single `null` threw `valueNotFound` and aborted the decode on both the session-key and OAuth paths. The damage went past a blank UI: `UsageHistoryStore.append` sits in the success branch only, so an affected account wrote nothing to the append-only NDJSON on every tick — a permanent, unrecoverable gap — and left a stale widget snapshot. Ports upstream `494957d`, which supersedes `3878868`.
- New `UsageError.usageDashboardUnavailable`, raised from `UsageResponse.isUsageDashboardUnavailable` before `toUsageData()` — which manufactures a 0% 7-day placeholder that would otherwise mask the condition. `member_dashboard_available` is decoded for logging and the diagnostic report but deliberately does not drive the verdict: its semantics are unverified, and if personal Pro/Max accounts also report `false` it would misjudge every healthy account. The verdict looks only at the data.
- The stale-data banner is gated on typed state, not on string comparison. `DataRefreshManager` publishes `errorRequiresFullScreen`, classified from the `UsageError` case itself; comparing `errorMessage` against `L.Error.*` would break on a language switch, since the message is a snapshot while those strings re-resolve per access. `isShowingStaleData` is a latch cleared only by a successful fetch, so the banner and the popover height don't blink while a retry is in flight, and it is suppressed after an account switch until that account succeeds once — otherwise a failed first fetch would label the previous account's numbers as cached data. Ports the view half of upstream `a23c801`.
- `OAuthCallbackServer` gained `deinit { listener?.cancel() }` (from upstream PR #77; the rest of that PR is Codex-specific or already better covered here). Written as a direct `cancel()` rather than `deinit { stop() }` — the shape the other deinits in this codebase use — because `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` makes `stop()` isolated, and that form is an error under the Swift 6 language mode.
- Settings layout ports the layout half of upstream `92223a2`: `alignment: .top` on the content frame, `Spacer(minLength: 0)` in AboutView, and a fixed-height toolbar button with a pinned 24×24 icon. Its copyright half is deliberately skipped — it adds a link to the upstream author and rolls the year back.
- 72 tests (+7): the all-null payload, a field absent entirely, flag-vs-data precedence, an empty `limits` array, `primaryLimit` falling back to `sevenDay`, and a fork-only regression pairing a null `five_hour` with populated `limits[]` to prove the position-fixed weekly slots still resolve.

## Heads-up on update

None. No entitlements or Keychain access groups changed — the Sparkle update installs seamlessly, **no re-login required**.

## Known limitations

- An account with no usage windows but with Extra Usage credit still fails the whole fetch rather than showing the Extra Usage row on its own. `fetchUsage` merges `async let main` / `async let extra`, and a throwing `main` discards `extra`. Unchanged from before this release — such accounts previously failed the same way, just with a worse message — and upstream behaves identically.
- `UsageError` and both service guards live in `ClaudeAPIService.swift`, which is not in the SwiftPM test target, so they carry no unit coverage. Only the `hasNoLimitData` / `isUsageDashboardUnavailable` predicates and the nil-tolerant `toUsageData()` are reachable from `swift test`.
- The settings-layout change is hardening, not a repair of an observed clipping: the fork's About tab is shorter than upstream's since the ko-fi and sponsor buttons were removed, so it currently fits, marginally. Not verified on screen.

## What stays unchanged

Weekly per-model limits keep the fork's position-fixed `legacyOpus` / `legacySonnet` slots with `scopedWeeklyModels` alongside, not upstream's single collapsed array. Rate-limit backoff, refresh tiers, and the OAuth loopback-peer hardening are all untouched.
