# U4Claude v1.6.4

Three upstream backports — one bug fix, one polish, one visual upgrade.

## What changed

- **Google sign-in via the WebLogin window now works.** Google's traditional OAuth flow uses `window.open()` to pop an auth window; without a `WKUIDelegate` the pop-up was silently dropped and login hung. Added a `UIDelegate` inner class that loads the request back into the same `WKWebView` so the OAuth round-trip stays coherent without needing a persistent data store. Also broadened `allowedDomains` from subdomain-specific entries (`accounts.google.com`, `www.google.com`, etc.) to base domains (`google.com`), and added `youtube.com` since Google's auth handshake bounces through `accounts.youtube.com/CheckConnection`. As a memory-hygiene side-effect, the WebLogin window now releases its `WKWebView` reference when the user closes via the window's red dot — previously the WebView lived on indefinitely in the background. Backported from upstream commit [`94dabbf`](https://github.com/f-is-h/Usage4Claude/commit/94dabbf) (closes upstream #49).

- **"View Claude Usage" menu item replaced with "Claude Status"**, pointing at [status.claude.com](https://status.claude.com). The old menu item just opened `claude.ai/settings/usage` in a browser — redundant with what U4Claude shows in its own popover, widget, and menu bar. The new item is actually useful during outages. The keyboard shortcut (`⌘⇧W`) is unchanged for muscle memory. All five locales updated with upstream's canonical translations. Backported from upstream commit [`5d022c5`](https://github.com/f-is-h/Usage4Claude/commit/5d022c5).

- **Detail rings now *visually* invert in remaining mode.** Previously the "show remaining" toggle (tap on a row) only swapped the subtitle text from reset time to remaining quota. Now the ring itself drains from the top — fill represents the *available* slice rather than the used slice — and the center label flips from "Used" to "Available". Animation curve switched from `.easeInOut` to a snappier spring (`response: 0.42, dampingFraction: 0.78`) so the ring fill, center label, and row text all settle together on toggle. The mode preference is also eager-initialized from `UserDefaults` at the `@State` declaration site, eliminating the one-frame flash on popover open where the ring used to render in "Used" then flip to "Available". Backported from upstream commit [`fdeb0c1`](https://github.com/f-is-h/Usage4Claude/commit/fdeb0c1).

## Deferred from the upstream port

- Upstream's `DetailUsageRingSweep` cosmetic flourish (a one-shot angular gradient sweep around the ring on mode toggle) wasn't ported. Our glass-tube rendering already has stacked `.shadow()` glow halos in the same visual band; layering a sweep gradient on top would likely muddle the effect. May revisit in a future release with a visual-tuning pass.

## Internal

- New pure-function helpers `UsageRingTrimRange` (struct) and `UsageRingDisplay` (enum with `clampedPercentage`, `displayedPercentage`, `usedFraction`, `displayedTrimRange`) in `Usage4Claude/Views/Components/UsageRowComponents.swift`. No SwiftUI dependencies — could be moved into the SwiftPM test target later if we want coverage of the trim-range math.
- WebLogin changes touch only `WebLoginCoordinator.swift` (UIDelegate + allowedDomains) and `WebLoginWindowManager.swift` (`willCloseNotification` observer). The 403-classification half of upstream commit [`d07e5dd`](https://github.com/f-is-h/Usage4Claude/commit/d07e5dd) was *not* backported — our fork's `ClaudeAPIService` already does finer-grained 403 discrimination via the `permission_error` JSON body type, predating upstream's HTML-vs-JSON heuristic. Upstream's `.default()` data store swap also skipped: our UIDelegate loads back into the same WebView, so `.nonPersistent()` still preserves session cookies across the OAuth chain.
- Build clean; 50/50 swift tests pass; zero compile warnings.
