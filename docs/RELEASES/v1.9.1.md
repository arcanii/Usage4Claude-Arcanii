# U4Claude v1.9.1

A bug-fix release: the desktop widget now agrees with the popover, and notifications behave when you switch accounts.

## What changed

- **Widget tiles show the real weekly model name.** v1.9.0 taught the popover to label weekly limits with the actual model (for example "Fable"), but the widget still had fixed "Opus" and "Sonnet" tiles — so the same number appeared under two different names depending on where you looked. The Large Dashboard and Extra Large widgets now use the model name reported by the API, falling back to the previous labels when the account still uses the older fixed fields.
- **Switching accounts no longer fires a false "limit reset" notification.** Usage was compared against the previous fetch even when that fetch belonged to a different account, and a changed reset time plus any lower percentage reads as a reset. Switching between accounts could therefore announce a reset that never happened. The comparison is now skipped for the first refresh after a switch.
- **Switching accounts no longer swallows a warning.** Notification records were kept per limit type but not per account, so a warning already sent for one account silently suppressed the same warning for another. Records are now tracked per account, and removing an account discards only its own records.

## Internal

- `UsageSnapshot` — the Codable payload the main app shares with the widget through the App Group — gained optional `opusModelName` / `sonnetModelName`, populated by `UsageSnapshotBridge`. The fields are optional and purely additive: during an update the widget can read a snapshot written by the older app, so absent keys must decode as nil rather than fail. No migration.
- `UsageSnapshot.swift` joined the SwiftPM test target, with guards for decoding a snapshot that predates the model names and for a model-name round trip. 65 tests pass; Debug and Release builds clean.
- `DataRefreshManager.prepareForAccountSwitch()` suppresses exactly one previous-vs-current comparison. It is invoked from the existing `.accountChanged` sink before the refetch, because ordering between two separate observers of the same notification is undefined.
- The never-called `resetAllNotificationStates()` was replaced by `resetNotificationStates(forAccountId:)`, wired into `removeAccount`.
- `.claude/scheduled_tasks.lock`, a runtime session lock committed with the original fork import, is no longer tracked.

## Heads-up on update

None. No entitlements or Keychain access groups changed, so the Sparkle update installs seamlessly — **no re-login required**.

## What stays unchanged

Single-account users are unaffected by the notification fixes. Accounts still reporting the older fixed weekly fields keep their existing labels in both the popover and the widget.
