# U4Claude v1.9.0

Weekly per-model limits are read and labeled correctly again, notifications actually appear, and the browser sign-in gains a fallback.

## What changed

- **Weekly per-model limits are back, with their real names.** Claude's usage API moved weekly per-model limits out of the dedicated `seven_day_opus` / `seven_day_sonnet` fields and into a `limits[]` array identified by model display name. On affected accounts v1.8.0 showed **no weekly model row at all** — the data was there, the app just wasn't reading it. The row now returns and is labeled with the actual model (for example "Fable") instead of a fixed "Opus Weekly" caption, falling back to the localized label for accounts still on the old fields. A third or later model now gets its own popover row rather than being dropped.
- **Notifications no longer vanish when the app is in front.** Usage and reset alerts were silently suppressed whenever the settings window or the popover was open — which is exactly when they most often fire. They now display as a banner with sound.
- **Sign-in recovers instead of dead-ending.** If the browser reaches the localhost callback page but the app never receives the redirect (seen with Arc and some Chromium builds), you can paste the callback link back into the sign-in window to finish. Retrying after a failed attempt no longer hangs on a stale callback, and an expired access token now refreshes itself instead of showing an error until the next scheduled refresh.
- **Requests report your real language.** The `accept-language` header was hardcoded to `zh-CN` for every user; it is now derived from your system's preferred languages.
- **Refresh timers no longer silently fail to start.** A timer scheduled from a background thread registered on a run loop that never ran, so it never fired.

## Internal

- Security: `PKCE` now checks the `SecRandomCopyBytes` status instead of ignoring it — a silent RNG failure would have left the `code_verifier` and `state` all-zero and predictable, defeating PKCE and the CSRF check.
- `UsageData` now keeps `legacyOpus` / `legacySonnet` as position-fixed slots with the API-ordered `limits[]` entries in `scopedWeeklyModels`; `opus` / `sonnet` / `overflowWeeklyModels` are computed resolvers. This deliberately diverges from upstream `59f4efd`, which folds both slots into one array and so promotes Sonnet into the Opus slot whenever Opus is absent — silent corruption here, because `UsageHistorySampleBridge` writes `data.opus` into the append-only NDJSON history. See `docs/UPSTREAM_CONTRIBUTIONS.md`.
- Concurrency: four `MenuBarManager` notification sinks now hop to the main thread before touching UI, timers and windows; `saveAccounts` snapshots the account list before its background write.
- Correctness: first-launch and reset-to-defaults now share one `customDisplayTypes` default; the OAuth `extra_usage` decode reports why it failed instead of a silent four-layer `try?`.
- CI: the release trigger passes the commit message through the environment rather than interpolating it into a heredoc.
- 63 tests pass (8 added since v1.8.0), covering the live API shape and guarding the weekly slot positions. Debug and Release builds clean, no new warnings.

## Heads-up on update

None. No Keychain access groups or entitlements changed since v1.8.0, so the Sparkle update installs seamlessly — **no re-login required**.

## What stays unchanged

Accounts whose API responses still carry `seven_day_opus` / `seven_day_sonnet` behave exactly as before, and those rows keep their existing localized labels. Session-key (cookie) accounts are untouched. The widget's App Group snapshot and the on-disk usage history keep their existing formats, so no migration runs.
