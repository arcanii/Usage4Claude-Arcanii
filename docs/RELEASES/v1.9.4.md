# U4Claude v1.9.4

One fix: the icons are back in the menu.

## What changed

- **Menu icons are visible again on macOS 27.** Right-clicking the menu bar item opens a menu whose seven entries — Accounts, General, Authentication, Check for Updates, About, Claude Status, Quit — each had an icon beside the label. On macOS 27 they all disappeared, leaving a column of bare text. macOS changed the rule: the system now decides whether a menu item's icon is drawn, and it hides them unless the app explicitly asks for them. The app now asks.

Nothing else changed. If you are on macOS 26, this release makes no visible difference.

## Internal

- Ports upstream `ecaa14d`. `NSMenuItem.h` in the macOS 27.0 SDK states the new behaviour directly: "in macOS 27 and later, AppKit determines the visibility of menu item images, and will typically hide images." Setting `image` alone is no longer enough; `preferredImageVisibility = .visible` opts back in.
- All seven icons are assigned through one function, `MenuBarUI.setMenuItemIcon`, so the declaration lives there and covers every item. Upstream needed a separate `assignIcon` helper because it also badges the update item; this fork left that to Sparkle and has no second assignment site. The account submenu sets only `item.state` and renders through `onStateImage`, so it was never affected.
- The `#available(macOS 27.0, *)` guard is required rather than defensive: the property is `API_AVAILABLE(macos(27.0))` and the deployment target is 26.0.
- **Deliberately not ported:** upstream's follow-up `cedffaa`, which reaches the same property by key-value coding in order to compile without the macOS 27 SDK. That workaround exists only because upstream's release CI is pinned to Xcode 26.6. This fork's CI is `latest-stable` and the build toolchain is Xcode 27.1 with the macOS 27.0 SDK, so the typed property is available and the compiler can check it.
- Found by delta audit #4 and confirmed against the installed SDK header rather than upstream's commit message. 72 tests pass; Debug and Release builds clean.

## Heads-up on update

None. No entitlements or Keychain access groups changed — the Sparkle update installs seamlessly, **no re-login required**.

## Still outstanding

Delta audit #4 found more than this, and the rest is not in this release. The two worth naming:

- **A rotated OAuth token can be written to the wrong account.** If you switch accounts in the moment a background token refresh completes, the new token can land in the other account's entry — and because these tokens rotate and the old one stops working immediately, both accounts can end up signed out. It needs two re-authentications to recover. This only affects people using more than one account.
- **A rate limit also blocks your own manual refresh.** The backoff added in v1.9.2 sits in front of every refresh path, including the refresh button, so pressing it during a backoff window does nothing and says nothing.

Both are written up with exact locations in [UPSTREAM_PORT_AUDIT.md](../UPSTREAM_PORT_AUDIT.md) under "Delta audit #4", and queued in [HANDOVER.md](../HANDOVER.md).
