# U4Claude v1.9.2

One fix: the app now backs off when Claude asks it to, instead of holding itself in a rate limit.

## What changed

- **"Too many requests" now clears itself.** Hitting a rate limit used to change nothing about how often the app polled — in smart mode it kept asking every 60 seconds, which renewed the limit instead of letting it lapse, so the error stuck around far longer than it should have. The app now pauses refreshing after a rate limit and resumes on its own, honoring the wait the server asks for when it sends one and otherwise waiting 2 minutes, then 4, then 8, up to half an hour. A single successful refresh clears the pause immediately.
- **Opening the popover no longer makes it worse.** Opening the detail view switches smart mode to its fastest tier. Since the natural response to seeing the error is to open the popover and look, that quietly pushed polling back to every 60 seconds and re-armed the problem. While a rate limit is in effect, opening the popover no longer changes the refresh tier.

## Internal

- `UsageError.rateLimited` now carries the server's `Retry-After` when present. `ClaudeAPIService.retryAfterSeconds(from:)` handles both forms RFC 9110 permits — a delta in seconds and an HTTP-date — and was verified against both, plus the negative, malformed and absent cases.
- The suppression check lives in `DataRefreshManager.fetchUsage()`, the single choke point every trigger shares (timer tick, popover open, wake from sleep, account switch, manual refresh), so no path can bypass the backoff. `Retry-After` takes precedence, clamped to 30s–30min so a very small value cannot produce a tight loop; otherwise the delay doubles from a 2-minute base to a 30-minute ceiling. A successful fetch clears the window and resets the escalation.
- 65 tests pass; Debug and Release builds clean.

## Heads-up on update

None. No entitlements or Keychain access groups changed — the Sparkle update installs seamlessly, **no re-login required**.

## What stays unchanged

Normal refresh behaviour is untouched when no rate limit is in effect: the same smart tiers (1 / 3 / 5 / 10 minutes) and fixed intervals as before, the same 30-second popover guard and 10-second manual-refresh debounce.
